PROJECT DETAILS

Chronos – Memory & Goal Tracking for AI Chats

What it is

A Chrome extension for ChatGPT and Gemini that organizes conversations into topics, saves restorable checkpoints, and tracks goals across chats.

The problem it solves

Keeping topics, checkpoints, and goals organized across AI conversations.

How it works

A WXT content script mounts the React interface in ChatGPT and Gemini. Platform adapters observe conversations, while validated runtime messages connect the interface to the background service worker. The worker owns IndexedDB repositories for sessions, checkpoints, and goals. The experimental topic-shift classifier uses EmbeddingGemma embeddings with Transformers.js and is excluded from normal production builds.

Architecture

Conversation state stays in extension-owned storage. The background service worker mediates access between the chat interface and the repositories.

Chat interface → durable conversation state

  1. ChatGPT / GeminiPlatform adapters observe the conversation and identify the active chat.
  2. React content scriptWXT mounts a Shadow DOM interface; session and mode controllers manage topics and checkpoints.
  3. Background service workerValidated runtime messages reach repository handlers; the worker owns storage access.
  4. IndexedDB · chronos-dbSessions, checkpoints, mode states, snapshots, and history persist across worker restarts.

Goals page → independent goal storage

  1. Extension Goals pageCreate goals, milestones, and tasks; link them to saved conversations.
  2. Goals message handlerAccepts extension-page requests, resolves chat references, and broadcasts changes.
  3. IndexedDB · chronos-goals-dbA separate database supports goals and backup import/export without rewriting conversation state.

Experimental analysis: the EmbeddingGemma / Transformers.js topic-shift classifier is a development research path. Its research entrypoints are excluded from normal production builds; it is not part of the core storage flow above.

Notes

The 99 test cases were written by me during development. The model is not enabled in production builds. The repository is private.

AgentOps – AI Agent Observability & Evaluation Platform

What it is

A multi-tenant AI agent observability and evaluation platform.

The problem it solves

Understanding agent traces, cost, latency, and failures, and checking regressions.

How it works

The Python SDK sends telemetry to the FastAPI ingestion API. Redis Streams queues events for workers that reconstruct trace/span hierarchies and persist them in PostgreSQL. The React console presents traces, evaluations, cost, and latency percentiles (p50–p99). Rule-based checks and LLM-as-a-judge evaluations support failure detection and safety-guarded replay. Docker Compose packages the API, workers, PostgreSQL, and Redis; Alembic manages migrations.

How the dashboard gets its data

The React console makes authenticated requests to FastAPI under /api/v1. In local development, Vite proxies these requests to the API on port 8000. The API reads persisted traces and computes the overview, cost, latency, and failure summaries returned to the interface.

The SDK ingestion path queues telemetry in Redis Streams for workers to reconstruct and persist traces. Docker Compose uses PostgreSQL and Redis. Local development defaults to SQLite and supports an in-memory queue with a worker running inside the API process.

Where the demo data comes from

The seed script creates the Acme AI demo workspace and its Production Agents project, then calls a simulator that generates agent events. The simulator sends those events directly through the ingestion worker and runs failure detection on the saved traces. These are synthetic executions processed by the backend, not production usage or benchmark results.

The Run agent control calls the same simulation endpoint, then refreshes the dashboard. The portfolio shows static screenshots of that application; it does not connect to the private AgentOps API.

Architecture

Telemetry is ingested asynchronously, reconstructed into traces, and queried through project-scoped APIs. Docker Compose configures PostgreSQL and Redis for the API and workers.

Telemetry ingestion → stored traces

  1. Python SDKBatches agent, tool, and LLM events for ingestion.
  2. FastAPI ingestionPOST /api/v1/telemetry/events validates the API key, event schema, and project ownership.
  3. Redis StreamsQueues accepted events for consumer-group processing.
  4. Telemetry workerDeduplicates event IDs, reconstructs trace/span relationships, and calculates token costs.
  5. PostgreSQLPersists events, traces, and spans. Redis messages are acknowledged after persistence.

Dashboard request → API response

  1. React consoleFetches overview, traces, metrics, failures, and alerts using a bearer token.
  2. FastAPI project APIsAuthorize access and call trace, metrics, evaluation, reliability, and replay services.
  3. Stored data → responseSQLAlchemy queries the database; API responses populate the console and its charts.

How the evidence demo gets its data

  1. Seed / Run agentCreates synthetic execution scenarios in the selected demo project.
  2. Demo simulator endpointCalls the same telemetry worker directly, bypassing Redis for this demo path.
  3. Database + failure scanStores reconstructed traces and scans them for failures; the console reads results through the APIs above.

Local development: the default database is SQLite. An in-memory queue fallback and an embedded API worker allow development without Redis. The screenshot data is synthetic demo activity, not production traffic.

Notes

The repository is private. No production deployment or throughput results are claimed.

In-Memory PDF & Markdown Dropper – Published on Chrome Web Store

What it is

A published Chrome extension for capturing webpages and AI conversations as vector PDFs or Markdown.

The problem it solves

Moving captured content into web drop areas without saving it to disk.

How it works

Chrome MV3, pdf-lib, and PDF.js support in-memory capture, PDF editing and merging, multi-tab batch capture, and drag-and-drop into web drop areas.

Capture, edit, and move

The side panel separates PDFs with images from text-only PDFs, with PDF-to-Markdown conversion available for text-only files. Capture multiple tabs, merge selected PDFs, and use either the inline editor or full-page studio to add annotations. The studio can stage a new copy or apply edits to the shelf.

Staged files stay in browser memory. A session notice explains that closing the panel or browser discards unsaved files.

Notes

Fully client-side with zero user data collection.
